# AdaFedGCDR 论文对比协议

## 当前执行范围

首先使用 Books 为目标域，CDs、Movies、Clothing 为源域。输入为带时间戳的 Amazon 评分交互，不使用评分值；按用户-域-物品去重，保留最早时间。扩大的候选子集包含4348名用户、104180条交互。

这是一组受控预算实验，不等同于原论文复现；正式发表前应补充更长训练预算的稳定性检查、其他目标域，以及全目录排序。原论文指标不与本实验数值直接比较。

## 数据与拆分

- 固定用户拆分种子2026：A基础组60%、B融合组20%、C验证组10%、D测试组10%。训练初始化种子采用2026、2027、2028，用户和候选集不随初始化种子改变。
- 源域交互严格早于每名用户第一次目标域交互。源域模型可以利用所有用户的这部分历史。
- 本轮合格用户需要11–100个目标域唯一物品，且至少一个首次目标域交互之前的源域交互。每个源域可用历史最多100个物品；这是小规模计算约束，必须披露其选择偏差。
- 初筛使用`crc32(user_id) % 20 == 0`，然后保留全部4348名合格用户。数据抽样不依据推荐效果或测试标签是否可推荐。
- 这是按用户交互顺序的离线前缀协议，不是全局时间切分，也不能当作真实上线时点模拟。

## 少交互协议：比较原版完整 FedGCDR

在k=1、3、5、10分别训练骨干。A/B的目标域交互是两种方法共同可用的训练监督，C/D仅暴露前k条交互。预测第k+1条；C标签只作验证和早停，D标签只作测试。C/D前缀可参与原版联邦训练，这是已见用户的稀疏历史实验，不声称测试用户隔离。

物品目录仅由A/B交互建立。目录外的C/D历史不参与模型训练，目录外标签单独计数；对于无目录内已见历史的样本，两方法共同排除并报告数量，避免将原版未训练的随机ID向量当作正常基线。

两个推荐头共享完全相同的源域模型、目标域骨干和物品表示。使用原版`Client`、`Server`、`GAT`和`MLP`，执行源域图学习、目标域普通GAT预训练、目标域迁移GAT、冻结GAT后MF微调。MF初始化来自迁移GAT用户输出。原版通过其最终用户表示评分；Ada通过对齐源域表示、目标历史均值与门控评分。新增门控在B组上学习。

原版MF根据C组NDCG@10早停。门控同样根据C组验证指标早停。禁止调用旧`main.py`中的测试集选轮和异常吞掉逻辑。原版算法文件保持不变。

该实验检验共享FedGCDR骨干后，新增表示融合头相对于原版评分头的效果，不能将结果泛化为所有独立训练版本的AdaFedGCDR对原版的优势。

## 严格冷启动协议

只有A组的目标交互训练骨干并建立物品目录；B只学习门控，C验证，D测试。测试k=0、1、3、5、10，不读取B/C/D目标域用户ID表示。原版FedGCDR不填入这一张表，避免把新的归纳适配器误称为原版。

完整方法、源域单独推荐、目标域单独推荐、固定0.5融合、仅数量门控、仅可靠性门控均使用相同冻结表示。可训练消融分别训练并选自己的验证checkpoint，避免直接复用完整模型参数造成不公平。目标域单独推荐仅在k>0有定义。

另加入独立目标域流行度基线。目标域单独推荐在所有历史物品均不在训练目录时按流行度回退，不借用源域表示；源域单独推荐没有源域信号时也按流行度回退。

按每名测试用户可用源域数量1/2/3分别报告指标。严格冷启动实验另在同时拥有Clothing和其他源域的共同测试用户上进行两项冻结表示敏感性检查：移除Clothing、将Clothing表示在不同用户之间循环打乱。原始和干扰输入使用同一标签、候选集和预训练门控；不把这个后处理敏感性测试误称为原版完整模型的源域消融。

## 固定标签检查

每个k都预测同一用户的第11条目标域交互，使用完全相同的99个负物品。少交互固定标签曲线采用第一条目标物品就在训练目录内的共同用户集，使各k可以使用相同用户。此项作为次要分析；主要调参仍只依据下一条交互验证指标。

## 默认计算预算

- 嵌入16维、两层原版GAT；user_batch=16、local_epoch=3。
- 每个源域5轮；目标域普通GAT5轮、迁移GAT5轮；MF最多20轮。
- 门控Adam学习率0.001，最多50轮；所有验证早停patience=5。
- 原版lr_gat=0.001、lr_mf=0.005；DP开关开启，eps=8、delta=1e-5。
- 使用原版逐Client训练，不使用`batched.py`，排除不同聚合和Adam状态语义对结论的影响。
- 三个训练种子保持完全相同的预算。这是预先设定的预算，不宣称已经收敛。扩大预算应全方法一起重跑并报告。

以上是代码噪声机制的相同配置，不是累计隐私预算相同的证明。本管线仍是集中式离线研究，不据此声明新增联邦隐私保证。

## 指标与统计

主指标NDCG@10，辅助HR@5/10、NDCG@5和目录覆盖率。每个正样本对应99个固定负物品，排除用户在本数据中的全部已知交互，未来交互仅用于离线负采样排除，不进入模型或物品目录选择。所有方法共享样本、标签和候选顺序。

原版与完整方法按用户配对比较；重复用户的多个k先取用户均值。三个种子分别算用户均值，再报告跨种子均值和样本标准差。配对bootstrap先对同一个用户跨种子平均，再重采样用户，不将三个种子当成三倍独立测试样本。固定标签、分阶段和消融作为辅助结果；禁止通过测试集选择最优源域、参数或种子。

本轮测试物品目录覆盖仍可能偏低，必须同时报告不可推荐比例。条件排序指标不能代替全体用户的端到端推荐效果。

## 实现与验证

- `model/adafedgcdr/paper.py`：协议输入、原版完整训练、独立门控训练。
- `scripts/run_paper_comparison.py`：多种子、固定候选、checkpoint、断点续跑、报告与配对统计。
- `tests/test_paper_protocol.py`：原生unittest可运行，检查未来目标交互和B组标签隔离、前缀训练输入、固定标签和零前缀边界。

运行示例：

```bash
python -m unittest tests.test_paper_protocol -v
python -m scripts.run_paper_comparison \
  --events artifacts/paper-four-domain/events.csv \
  --out artifacts/paper-four-domain/results \
  --seeds 2026,2027,2028 --device cuda:0
```

输出逐种子、逐协议的骨干和三个独立可训练门控checkpoint，完整指标及用户记录；总表位于`summary.json`、`report.md`，运行状态与代码/数据哈希位于`run.json`。前一轮1000人结果不与新的协议混合平均。

多个独立初始化种子可以使用`python -m scripts.run_paper_suite`运行；该入口为每个种子建立独立日志和输出目录，并维护`suite.json`及跨种子汇总。原版算法文件未修改，但其逐Client训练会显著慢于旧的批处理加速实验。
